# 陆道山 个人课程总结报告

## 一、本人在本综合项目实践中承担的工作

在本项目中，我担任**管理端前端开发工程师**，负责 Vue 3 管理后台的全部页面开发、数据对接和数据可视化工作。

### 1.1 管理端架构搭建

- 搭建 Vue 3 + Vite + Element Plus + Pinia 管理后台项目框架
- 封装 axios 实例（`src/api/request.js`），实现：
  - 请求拦截器：自动从 localStorage 读取 Token 并附加到请求头
  - 响应拦截器：统一处理 `code !== 200` 的错误提示，Token 过期/401 时自动清除登录状态并跳转登录页
- 实现 Vue Router 路由守卫（`router.beforeEach`）：未登录用户只能访问登录页，自动跳转；已登录用户不能再次访问登录页
- 按模块封装 API 层（`auth.js`、`user.js`、`product.js`、`category.js` 等），每个模块管理一类接口

### 1.2 管理端页面开发

**第一/二阶段完成的核心页面：**

- **登录页**（`views/login/`）：管理员用户名/密码登录表单，登录成功后存储 Token 和用户信息到 localStorage，自动跳转到数据看板
- **用户管理**（`views/user/`）：分页列表展示所有用户（头像、昵称、注册时间、状态），搜索筛选功能，封禁/解封用户操作（调用 `/api/user/updateStatus`），操作后实时刷新列表
- **商品审核**（`views/product/`）：Tab 切换按商品状态筛选（待审核/在售/下架/售出），分页展示商品列表（标题、图片、价格、卖家、发布时间），审核通过/驳回操作（调用 `/api/product/audit`），操作后状态实时更新
- **数据看板**（`views/dashboard/`）：四项统计卡片（用户总数、待审核商品数、在售商品数、已售出商品数）从后端实时获取数据，待审核商品快速处理列表，引入 ECharts 实现用户增长趋势折线图和每日商品发布量柱状图

**第三阶段新增/完善的页面：**

- **分类管理**（`views/category/`）：分类列表展示，支持新增/编辑/删除分类，分类名称和排序字段管理
- **实名状态查看**（`views/verification/`）：查看学生的实名认证记录（姓名、学号、学院、专业、认证状态），支持按认证状态筛选
- **评论管理**（`views/comment/`）：查看所有商品评论列表（评论内容、用户、商品、时间），支持删除违规评论操作

### 1.3 从 Mock 到真实 API 的完整改造

管理端最初使用静态 Mock 数据快速搭建页面原型，在第二阶段逐步将所有页面对接真实后端 API：

- 用户管理：`/api/user/list`（分页）+ `/api/user/updateStatus`（封禁/解封）
- 商品审核：`/api/product/list`（按 status 筛选）+ `/api/product/audit`（审核操作）
- 数据看板：对接多项统计 API 获取实时数字和图表数据
- 分类管理：`/api/category/*` CRUD 接口
- 评论管理：`/api/comment/list` + 删除接口

## 三、遇到的问题及解决方法

### 问题一：Mock 数据到真实 API 的平滑切换

**现象**：管理端页面最初全部使用前端静态 Mock 数据开发，切换到真实 API 后发现返回的数据结构、字段名、分页格式与 Mock 数据不一致。

**解决**：采用渐进式切换策略——先选择一个接口较稳定的页面（如用户管理）作为试点，确认数据结构对齐后逐步推广到其他页面。每次切换后做完整的页面功能验证。

### 问题二：ECharts 图表数据格式转换

**现象**：后端返回的统计数据是简单的数值或键值对列表，但 ECharts 要求特定的 `xAxis.data` 和 `series.data` 数组格式。

**解决**：在组件中编写数据转换函数，将从后端获取的原始数据映射为 ECharts 所需的格式。例如将 `[{ date: "2026-05-01", count: 23 }]` 转换为 `xAxis: ["2026-05-01"]` 和 `series: [23]`。

### 问题三：Element Plus 分页组件与后端分页结构的适配

**现象**：Element Plus 的 `el-pagination` 组件使用 `current-page` 和 `page-size` 参数，但后端需要 `current` 和 `size` 参数，且总条数字段名也不一致。

**解决**：封装一个通用的分页参数转换工具，在请求拦截层统一处理参数名的映射。总条数从 `data.total` 提取并绑定到 `el-pagination` 的 `total` 属性。

### 问题四：路由守卫与 Token 过期处理

**现象**：管理员登录后如果长时间不操作，Redis 中 Token 过期，再次请求时会收到 401 错误，但页面不会自动跳转登录页。

**解决**：在 axios 响应拦截器中捕获 401 状态码，自动清除 localStorage 中的 Token 和用户信息，并使用 `router.push('/login')` 跳转到登录页。

### 问题五：管理端多 Tab 状态保持

**现象**：商品审核页面有多个状态 Tab（待审核/在售/下架/售出），用户切换 Tab 后刷新页面会丢失当前 Tab 状态。

**解决**：将当前 Tab 状态同步到 URL 的 query 参数中（如 `?status=0`），页面加载时从 URL 读取初始 Tab 状态，保证刷新后状态不丢失。

## 四、总结与展望

### 4.1 总结

通过本次项目实践，我在管理端前端开发和数据可视化方面有了显著提升：

**技术层面**：掌握了 Vue 3 Composition API + Element Plus 组件库的完整开发流程，学会了 ECharts 图表库的集成和数据格式转换。从 Mock 数据到真实 API 的切换过程，让我深刻理解了前端开发中"先原型后对接"的工作方式。

**协作层面**：管理端作为平台治理的入口，与后端接口的依赖非常紧密。通过与后端同学持续沟通接口格式和字段含义，我学会了在开发前先确认接口文档，避免返工。

**数据思维**：数据看板的开发让我开始思考"什么样的数据对管理员和运营者是有意义的"——不仅要展示数字，还要展示趋势和对比。

### 4.2 展望

- 增加更多维度的数据看板（如分类销售占比饼图、热门商品排行）
- 引入导出功能（如用户列表、订单列表导出 Excel）
- 优化管理端的移动端响应式适配

## 五、对课程的建议

1. 管理端的开发往往需要后端接口先准备好才能联调，建议安排更紧密的前后端配合节奏，或者提供 Mock 数据服务
2. 数据可视化是管理后台的重要组成部分，建议课程增加对可视化工具链（如 ECharts、D3.js）的简单介绍
3. 管理端的功能验收建议有明确的标准（如每个页面至少有查询和核心操作功能），便于前端同学自测
