# B 范围平台完善实施计划

> **文档性质：规划阶段实施计划**
> 本文档编写于 B 范围功能实施之前，属于规划阶段文档。
> 实际实现情况请参见 `B范围实现说明.md` 和 `B范围完整验证手册.md`。
> 本文档保留供参考实施思路和任务分解过程。

## 一、实施目标

本计划用于指导校园二手交易平台 B 范围能力完善工作。实施目标是在不改变现有总体架构的前提下，补齐微信登录、实名校验、地图选点、收藏评论、评价信用、轻量推荐和后台治理等能力，并通过测试和文档整理形成可验收版本。

## 二、实施原则

- 保持现有架构，不额外拆分微服务；
- 优先完成主链路闭环，再补充增强能力；
- 后端接口、数据库结构、前端页面和文档同步演进；
- 第三方密钥使用环境变量，不写入源码；
- 对真实接入和模拟实现进行明确说明；
- 每个关键后端服务尽量配套单元测试。

## 三、任务拆解

### 1. 配置与数据库基线

实施内容：

- 将微信和腾讯地图配置改为环境变量读取；
- 补充数据库结构，增加实名、分类、收藏、评论、评价、行为记录、聊天会话和消息等表；
- 保留基础数据初始化脚本。

验证方式：

- 后端能够读取环境变量；
- 数据库脚本可手动执行；
- 后端基础测试通过。

### 2. 微信小程序登录

实施内容：

- 用户端调用 `uni.login` 获取 code；
- 后端调用微信 `code2Session` 获取 `openid`；
- 根据 `openid` 创建或查询用户；
- 生成 Redis Token；
- 返回用户信息和实名状态。

验证方式：

- 小程序端可以完成登录；
- 本地保存 `user_token` 和 `user_info`；
- 管理端原账号密码登录不受影响。

### 3. 学号实名与发布门禁

实施内容：

- 增加实名提交接口；
- 使用 `biz_student_roster` 进行精确匹配；
- 实名成功后更新用户状态为 `VERIFIED`；
- 商品发布接口校验用户是否实名。

验证方式：

- 正确学籍信息实名成功；
- 错误信息实名失败；
- 未实名用户不能发布商品；
- 已实名用户可以进入发布流程。

### 4. 动态分类与后台分类管理

实施内容：

- 后端提供分类查询和管理接口；
- 用户端首页和发布页从后端加载分类；
- 管理端支持分类新增、修改、排序和启用状态维护。

验证方式：

- 用户端分类展示与后端数据一致；
- 管理端修改分类后，用户端能感知变化。

### 5. 腾讯地图面交点

实施内容：

- 后端封装腾讯地图搜索和逆地址解析；
- 发布页支持选择面交点；
- 商品保存面交点名称、地址和经纬度；
- 详情页展示面交点信息。

验证方式：

- 地点搜索能返回结果；
- 发布商品时能保存面交点；
- 商品详情能展示面交地点。

### 6. 收藏与评论

实施内容：

- 商品详情页支持收藏和取消收藏；
- 商品详情页支持评论列表和发表评论；
- 后端维护收藏、评论数据和相关计数；
- 将收藏、评论行为写入用户行为记录。

验证方式：

- 收藏操作幂等；
- 取消收藏后状态正确；
- 评论不能为空；
- 评论发布后刷新可见。

### 7. 订单、评价与信用分

实施内容：

- 补齐“我买到的”和“我卖出的”订单视图；
- 支持订单取消和确认收货；
- 订单完成后支持买家评价卖家、卖家评价买家；
- 防止重复评价；
- 根据评价结果更新用户评分和信用分。

验证方式：

- 买家能查看订单并确认收货；
- 卖家能查看卖出订单；
- 双方能分别评价；
- 重复评价被拦截；
- 信用分和评分更新。

### 8. 即时通讯增强

实施内容：

- 使用 WebSocket 支持买卖双方实时聊天；
- 建立会话和消息表；
- 消息发送时持久化；
- 聊天页进入时加载历史消息。

验证方式：

- WebSocket 可建立连接；
- 消息能实时发送；
- 刷新或重进聊天页后能看到历史消息。

### 9. 轻量推荐

实施内容：

- 记录用户浏览、收藏、评论、下单等行为；
- 基于分类偏好、互动行为和商品热度进行推荐排序；
- 首页展示推荐商品区域。

验证方式：

- 用户产生行为后，推荐结果能体现一定偏好；
- 推荐接口无异常；
- 首页推荐区域可以正常渲染。

### 10. 管理端治理能力

实施内容：

- 增加实名状态查看页面；
- 增加评论管理页面；
- 完善分类管理页面；
- 完善数据看板趋势图。

验证方式：

- 管理员可以查看实名用户；
- 管理员可以管理评论状态；
- 分类管理正常；
- 数据看板正常加载。

### 11. 文档与验收

实施内容：

- 更新系统设计说明；
- 整理实现说明；
- 整理完整验证手册；
- 整理阶段工作小结；
- 准备提交 GitHub 的中文 README 和 `.gitignore`。

验证方式：

- 文档与实际实现一致；
- 启动步骤可复现；
- 验收清单可逐项执行；
- 仓库不包含密钥、构建产物和个人草稿。

## 四、最终验收标准

系统达到以下条件后，可作为 B 范围版本进行课程验收：

- 后端测试通过；
- MySQL、Redis、后端、用户端、管理端可启动；
- 微信登录真实打通；
- 实名校验成功和失败路径都可验证；
- 未实名禁止发布；
- 商品发布、审核、详情展示可用；
- 地图面交点选择和展示可用；
- 收藏、评论、聊天可用；
- 下单、确认收货、双方评价可用；
- 信用分更新可验证；
- 首页推荐可展示；
- 管理端分类、实名状态、评论治理和数据看板可用；
- 关键截图、日志和测试输出已留存；
- 公开仓库不包含真实密钥和构建产物。
