# B 范围平台完善设计说明

> **文档性质：规划阶段设计文档**
> 本文档编写于 B 范围功能实施之前，属于规划设计文档。
> 实际实现情况请参见 `B范围实现说明.md` 和 `B范围完整验证手册.md`。
> 本文档保留供参考设计思路和决策过程。

## 一、设计目标

本阶段目标是在已有校园二手交易平台 MVP 的基础上，补齐课程验收所需的 B 范围能力，使系统从“主链路可演示”进一步提升为“功能较完整、边界清晰、可复现验证”的版本。

设计重点包括：

- 用户端真实接入微信小程序登录；
- 使用本地权威学籍名单完成校园实名校验；
- 商品发布支持动态分类、图片上传和腾讯地图面交点选择；
- 商品详情支持收藏、评论和聊天；
- 订单流程支持买家订单、卖家订单、确认收货和双方评价；
- 后端维护信用分、评价记录和用户行为；
- 首页提供轻量推荐；
- 管理端补齐分类管理、实名状态查看、评论治理和数据看板；
- 文档和验证手册能够支撑课程验收与答辩。

## 二、总体架构

系统继续采用现有前后端分离架构，不重新拆分服务，也不引入额外复杂中间件。

- 后端：Spring Boot + MyBatis-Plus + MySQL + Redis
- 用户端：Uni-app，小程序优先
- 管理端：Vue 3 + Element Plus
- 第三方服务：微信小程序登录、腾讯地图 WebService
- 实时通信：WebSocket

后端仍作为核心业务中台，负责身份识别、业务校验、数据持久化和第三方服务封装；用户端负责真实交易流程体验；管理端负责平台治理和数据查看。

## 三、核心模块设计

### 1. 微信登录

用户端通过 `uni.login` 获取临时 code，后端调用微信 `code2Session` 换取 `openid`。后端根据 `openid` 查找或创建用户，并生成 Redis Token 返回给前端。

管理端仍保留原有账号密码登录，不与用户端微信登录混用。

### 2. 学号实名

当前课程环境无法直接接入学校官方认证系统，因此使用本地 `biz_student_roster` 表作为权威名单模拟数据源。用户提交学号、姓名、学院、专业、年级和身份证后四位后，后端进行精确匹配。

实名成功后，用户状态更新为 `VERIFIED`。商品发布等关键操作需要校验实名状态。

该设计保留可替换边界：后续如果获得学校官方接口，只需要替换实名服务的数据源，不需要改变前端流程和主要业务接口。

### 3. 动态分类

商品分类由后端统一维护，用户端首页、发布页和管理端商品相关页面均通过分类接口获取数据。管理端提供分类新增、修改、排序和启用状态管理，避免前端硬编码分类导致口径不一致。

### 4. 腾讯地图面交点

商品发布时，用户可以通过腾讯地图 WebService 搜索校内面交点。后端封装地图搜索与逆地址解析能力，商品保存时记录面交点名称、地址、经纬度等字段。

商品详情页展示面交点信息，增强校园线下交易场景的真实性。

### 5. 收藏与评论

商品详情页支持收藏和评论。收藏需要保证同一用户对同一商品的操作幂等，评论需要校验内容为空等异常情况。后端记录收藏和评论数据，并为推荐服务提供用户行为信号。

### 6. 订单、评价与信用分

订单流程从单纯下单扩展到完整交易闭环：

- 买家下单；
- 买家查看“我买到的”；
- 卖家查看“我卖出的”；
- 买家取消订单或确认收货；
- 订单完成后买家评价卖家；
- 卖家评价买家；
- 后端根据评价结果更新用户评分和信用分。

评价需要防止重复提交，并校验评价人是否属于订单买卖双方。

### 7. 即时通讯

系统使用 WebSocket 支持买卖双方围绕商品进行实时聊天。后端维护会话和消息记录，支持历史消息查询，保证刷新或重新进入聊天页后可以恢复会话内容。

### 8. 轻量推荐

推荐服务不引入复杂机器学习模型，而是基于课程项目可控范围设计轻量规则：

- 用户分类偏好；
- 收藏行为；
- 评论行为；
- 下单行为；
- 商品热度和时间因素。

首页展示推荐商品列表，用于体现平台的个性化和运营能力。

### 9. 管理端治理

管理端在原有用户管理和商品审核基础上，继续补齐：

- 分类管理；
- 实名状态查看；
- 评论管理；
- 用户增长和商品发布趋势图。

管理端目标是支撑课程验收时展示平台治理能力，而不只是展示用户侧交易流程。

## 四、数据设计补充

本阶段新增或重点使用的数据表包括：

- `biz_student_roster`：本地实名名单；
- `biz_category`：商品分类；
- `biz_favorite`：商品收藏；
- `biz_product_comment`：商品评论；
- `biz_order_review`：订单评价；
- `biz_user_behavior`：用户行为记录；
- `biz_chat_session`：聊天会话；
- `biz_chat_message`：聊天消息。

这些表围绕实名、互动、评价、推荐和聊天能力展开，支撑 B 范围功能完整落地。

## 五、边界说明

当前版本真实接入：

- 微信小程序登录；
- 腾讯地图 WebService。

当前版本模拟但可替换：

- 学校实名系统：使用本地学籍名单模拟权威数据源。

当前版本不包含：

- 学校官方认证接口直连；
- 真实线上支付；
- 机器学习推荐；
- 生产环境部署与公网域名配置。

## 六、验证策略

后端通过单元测试覆盖关键服务逻辑，包括微信登录、实名校验、分类、地图、收藏、评论、评价和推荐。

用户端和管理端通过手动验收清单进行验证，重点检查：

- 登录；
- 实名；
- 发布；
- 审核；
- 聊天；
- 下单；
- 收货；
- 评价；
- 推荐；
- 后台治理。

最终验收需要保留截图、测试输出和关键日志，确保结果可复现、可说明。
